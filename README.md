# Vanilla Server-Side

Independent, self-hosted web analytics by František Bujnovský. A small TypeScript tracker and collector send a parallel event stream to Google Analytics through its documented Measurement Protocol. Free to run and adapt under the MIT license.

Your existing Google Analytics tag through GTM stays unchanged. **Create a second, separate property for Vanilla. Never use the property used by your regular tag.** This separation prevents cross-pipeline duplicates and lets you compare the two properties. A Google tag is optional; no GTM reconfiguration is required.

```text
Website ── existing GTM / Google tag ────────── regular property
       └── Vanilla tracker ── your server ── MP ── separate property
```

Small by design: no database, no tag manager server container, no vendor account. Signed server cookies, consent gates, bounded memory queues, explicit event allowlists and a single Google transport module keep the behavior inspectable.

## Start

Follow [INSTALL.md](INSTALL.md) for a fresh Ubuntu/Debian VPS, DNS and consent setup.

```sh
git clone https://github.com/Narrativva-Labs/vanilla-server-side.git
cd vanilla-server-side
./install.sh
```

Insert the script tag printed by the installer once. Public routes are /s.js (script), /e (events), /p (consent withdrawal) and /health (status); event and withdrawal URLs resolve relative to the script URL, including any proxy prefix. Each operator hosts their own server. For development on Node 24: `npm ci && npm test && npm run typecheck && npm run build`.

## Modes

| | Cookie (default) | Cookieless |
| --- | --- | --- |
| Analytics granted | Send | Send |
| Analytics unknown | Wait in RAM up to 2 seconds, then drop | Wait up to 2 seconds, then send with advertising denied |
| Analytics denied | Stop, clear queue and request cookie deletion | Stop and clear RAM |
| Identity | Server-generated GA-format random ID in signed cookie | Random ID in page memory only |
| Storage | First-party HttpOnly Secure SameSite=Lax cookie | No cookies or browser storage |
| Geography | Actual client IP sent as MP `ip_override` after consent | Never sends `ip_override`; geography may be unavailable |

Cookie sessions expire after 30 minutes of inactivity; the signed cookie holds all session state. The identity cookie requests a 400-day lifetime; browsers may shorten it or delete it earlier. No Google cookies are read. `COOKIE_SECRET` is generated by the installer; keep it private. `COOKIE_DOMAIN` defaults to the hostname of `SITE_ORIGIN` with a leading www removed, matching the installer. Both hosts must be within that domain and HTTPS. CORS permits only `SITE_ORIGIN`, with credentials. The collector trusts exactly one proxy hop in production: keep port 3000 private behind the provided Caddy service.

## Events and consent

Both modes automatically send initial and SPA page views (pushState, replaceState, popstate), including the page title. Automatic page and referrer URLs always remove credentials, fragments and non-UTM query parameters before leaving the browser. Repeated notifications of the same URL and external page_view events do not duplicate them. Visible time starts only at an effective analytics grant and is sent as `engagement_time_msec`; hiding/leaving sends a small immediate `page_engagement` request outside the ordinary queue. Requests use fetch keepalive with a 32 KiB UTF-8 body guard. The server limits final MP events to 25 parameters, prioritizes automatic fields, truncates page text to 100 characters, and drops invalid custom fields with diagnostics. Ecommerce items keep documented item fields plus up to 27 custom parameters. Browsers can still lose requests on shutdown or when their keepalive quota is exhausted.

Both object dataLayer events and gtag event commands work in both modes, including items present before the script loads:

```js
window.dataLayer = window.dataLayer || [];
dataLayer.push({
  event: "purchase",
  ecommerce: {
    transaction_id: "order-123", currency: "EUR", value: 42,
    items: [{ item_id: "book", price: 42, quantity: 1 }]
  }
});
```

`TRACKED_EVENTS` defaults to standard ecommerce events, generate_lead, sign_up, login and search (see [.env.example](.env.example)). Purchase transaction IDs are deduplicated in page memory; request UUIDs are deduplicated briefly on the server. Neither is durable across restarts.

Direct Google consent commands take precedence over Cookiebot and CookieConsent fallbacks. Regional defaults remain unresolved until a direct Google consent update; CMP fallback cannot resolve them; wait_for_update is capped at 2 seconds. GTM's internal Consent API alone is not visible to this script. Advertising permissions reflect the actual state, unknown means DENIED, and cookieless always denies advertising. See the [consent setup](INSTALL.md#connect-your-consent-banner).

At session start, campaign_details uses UTM fields, otherwise gclid implies google/cpc without transmitting the ID, otherwise common search referrers imply organic, external hosts referral, and no external referrer direct. Cookieless never accesses storage. Automatic URL cleaning is not a general PII filter: never put personal information in event values, URL paths, titles or UTM fields.

## Honest limits

Safari may cap this server-set identity cookie to seven days when it detects third-party CNAME or IP-address cloaking. For IPv4 this applies when the tracker and the website do not share the same /16 prefix; for IPv6, the same /64. A same-origin endpoint or matching IP prefix may avoid this particular cap, but does not guarantee that the cookie will persist for its requested 400-day lifetime. See [WebKit tracking prevention](https://webkit.org/tracking-prevention/).

The server refreshes the cookie after each successfully delivered, non-deduplicated collection request unless the identity has been revoked, so regular returning visitors renew its expiry, subject to browser limits.

Measurement Protocol provides **partial reporting**, not a replacement for all browser tagging features. Google's documented session attribution use cases often assume matching tagged activity, which this independent property intentionally lacks. Source/channel, session and user reports may differ or remain incomplete. Campaign details are not displayed as events in DebugView. HTTP 2xx means Google received the request, not that the data passed validation or appeared in reports. Compare both properties with these limits in mind.

Google Ads is unsupported. There is no cross-domain identity, durable queue, multi-site routing, fingerprinting, database or automatic enhanced measurement beyond page views and engagement. A short process-local bridge coordinates concurrent first requests before the browser receives its cookie; it is not durable across restarts. Cookie state is signed, not encrypted. Consent withdrawal stops future collection but cannot retract requests already delivered. Cookie deletion needs the collector to be reachable.

This project makes no claim of automatic legal compliance; choose consent behavior and disclosures appropriate to your site. MP field choices follow the [reference](https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference), [events reference](https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference/events#campaign_details) and [use cases](https://developers.google.com/analytics/devguides/collection/protocol/ga4/use-cases).

GET /health returns delivery counts, errors and last successful Google HTTP delivery time, without visitor data. Application errors log only an outcome. Caddy error logs can contain client and request metadata during proxy failures; Compose rotates all service logs to three 10 MB files. Limits are 300 collector requests/minute/IP, 10 concurrent deliveries/IP and 100 concurrent deliveries globally. See [design decisions](docs/decisions.md) and [maintenance](INSTALL.md#updates-and-maintenance).
